Asset2D (non-parametric, translate-only) implemented 2026-07-13 on top of commit 4c6662a.

**Data model** (RenderPage2D.h / -DirectX12.h): every Cad2D*RecordCPU gained `parentObjectId`
(0 = plain page object). `Cad2DAssetDefinitionRecordCPU` (assetNumber = random 6-digit unique
per tab, baseX/baseY = bbox center) + `Cad2DAssetInsertRecordCPU` (definitionObjectId, x, y) live
in `TabCad2DStorage::assetDefinitionRecords/assetInsertRecords` under cpuRecordsMutex.
Key trick: definition master geometry = ordinary records with `containerMemoryId = 0` +
parentObjectId = definition → never rendered/hit-tested/zoom-fit (every loop filters by
container == page; copy thread skips container-0 commands), so the draw side needed zero changes.

**Flows** (RenderPage2D.cpp): `Cad2DCreateAssetFromSelection` (CREATE_ASSET2D ribbon → ACTION_TYPE
30028) re-parents originals to insert #1; `Cad2DBeginAssetInsert`/`HandleAssetInsertClick`
(INSERT_ASSET2D = 3125987404 → 30029) copy+translate masters per click, mode stays armed, ESC
exits. Ctrl+click multi-select toggles (VK_CONTROL now tracked in विश्वकर्मा.cpp KEYDOWN/KEYUP);
clicking an instance member selects the whole instance via parentObjectId scan.

**Persistence** (ObjectType 22/23, DataStorage_ASSET2D_{DEFINITION,INSERT}.proto):
- SQLite parent_id chain: member→insert→page; masters→definition; definitions top-level (NULL).
- **Gotcha 1**: FK is checked per INSERT statement → definition/insert rows must be pushed into
  `rows` BEFORE the geometry rows referencing them (done in BuildRowsFromTab).
- **Gotcha 2**: member rows can have LOWER object_ids than their owning insert (originals predate
  asset creation) → LoadYyyIntoTab buffers all 2D geometry and appends in a second phase after the
  full scan (`resolve2DGeometryParent`); never revert to inline appends or late copy-thread
  upserts will clobber corrected containers.
- schema_catalog_version bumped 7→8.

**UI**: reusable `UIDropdownState` + `BuildUIDropdown(...)` (UserInterface.h/.cpp) — free
function, ASCII items, handles own hit-test, advances vertex counters itself (raw PushRect does
NOT advance; BuildUIOverlay's local pushRect lambda does). Insert Asset pane shares the right
pane slot with the properties pane (assetInsertPaneOpen vs rightPaneOpen on SingleUIWindow,
mutually exclusive); dropdown writes `TabCad2DStorage::assetInsertSelectedDefinitionId` (atomic,
UI thread → engineering thread; 0/stale falls back to first definition).

**Why:** the parent-property design was the user's explicit spec; keeps GPU pipeline untouched.
**How to apply:** for EDIT_EXPLODE just clear members' parentObjectId.
MVP limitations: Copy/Mirror/Offset detach copies (asNewObject clears parentObjectId);
Move/Rotate keep membership; no definition delete UI; inserts are translate-only (no rot/scale).

**DXF asset import** (next.md IMPLEMENTED, same session): ExtensionIPC.proto adds
CreateAsset2DBatch { Asset2DDefinitionImport(asset_key,name,base_x/y,lines/texts/polygons),
Asset2DInsertImport(asset_key,x,y) } (WorkerToHost oneof #5). Host: ImportedPage2DContent gained
assetDefinitions/assetInserts; AppendValidatedAsset2DBatch reuses ConvertValidated2D{Line,Text,

ImportDxfFileIntoTab builds masters and calls shared `Cad2DCreateAssetDefinition` (hidden masters,
container 0, random number) + `Cad2DInstantiateAsset(tab,container,defId,x,y)` (extracted from the
click path — both now share it). Python (extensions/Interoperability-DXF): DXF reader now parses
BLOCKS into doc.blocks{name:Block(base,entities)} + INSERT entity (`_parse_entity_run` shared by
ENTITIES + block bodies); main.py `resolve_block_geometry` recursively flattens nested INSERTs
(cache + visiting cycle guard); base+masters raw block frame, only insert points get the recenter
offset (world = master + (insert - base) stays consistent); `send_asset2d_batch` in
vishwakarma_api.py; skip '*' system blocks. ExtensionIPC_pb2.py is regenerated by

**Policy change 2026-07-13 (user decision)**: INSERTs are NEVER exploded — every named, defined,
non-empty block INSERT becomes an Asset2DInsert. Nested INSERTs inside a block still flatten
WITH their local transforms via `transform_geometry`.

**Per-instance transforms 2026-07-13 (same day, superseding translate-only)**: Asset2DInsert
carries scaleX/scaleY/rotationDegrees end-to-end (DataStorage_ASSET2D_INSERT.proto fields 4-6,
kAsset2DInsertSchemaVersion 1→2 — loader treats scale (0,0) as identity for v1 rows; ExtensionIPC
Asset2DInsertImport fields 4-6; Cad2DAssetInsertRecordCPU; ImportedAsset2DInsert). The transform
is BAKED into member records by `Cad2DInstantiateAsset(tab, container, defId, x, y, sx=1, sy=1,
rotDeg=0)`: member = insert + R(θ)·S(sx,sy)·(master−base). Angle fields use the SAME conventions
as EDIT_ROTATE/EDIT_MIRROR in ApplyTransform2DToSelection: negative-scale decomposition (both
axes neg → θ+180°; one neg → reflection, φ=90° for negX / φ=0 for negY), polygon param-angle
a→−θ (and 180−2φ−a under mirror), ellipse/arc/text rot→rot+θ (2φ−rot under mirror), arc
start/end swap iff mirrored, radii approx (circle/polygon ×max|s|, ellipse/arc per-axis, text
height ×|sy|). Host validation: scale finite, |s| in [1e-9, 1e9]. Worker sends real DXF
x_scale/y_scale/rotation; skips |scale|<1e-9 as 'INSERT (degenerate scale)'; MINSERT array cell
offsets get scaled+rotated. GPU pipeline still untouched (members are flat records). next.md is
now stale (still describes translate-only MVP).
**No multi-pass DXF scan needed**: read_dxf_bytes parses the whole file into DxfDocument before
any block resolution (resolve_block_geometry is lazy, post-parse), so INSERT-before-BLOCK file
order is harmless — verified on build/DXF-DATASET (up to 338 forward refs in one file, 0
unresolved). All 7 dataset files pass an e2e worker-over-pipes run with a host-validation replica
(scratchpad run_worker_e2e.py pattern: fresh pb2 via protoc, subprocess main.py, length-prefixed
stream checks). Dataset maxima: 595 blocks, ~1.6k entities/block — far below host caps
(8192 defs / 200k masters / 1M inserts), so worker needs no cap guards.
